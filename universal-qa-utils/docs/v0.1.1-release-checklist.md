# Release checklist — universal-qa-utils 0.1.1

This checklist records the unpublished 0.1.1 maintenance work. That version was not released. The release candidate is 0.2.0, and `LIBRARY_VERSION` is `0.2.0`.

Status: **in development**. Do not tag, publish a GitHub release, or upload this version until the acceptance criteria below are met and explicitly approved.

Version 0.1.0 remains the production release: https://pypi.org/project/universal-qa-utils/0.1.0/. Tag `v0.1.0` points at `cd1e74cc3a07727059d60fa088f95b109a371d76`. This checklist does not move that tag or replace those artifacts.

## Compatibility

0.1.1 is a backward-compatible maintenance release.

| Contract | Assessment |
| --- | --- |
| Python | `>=3.11` |
| Required dependencies | `pandas>=2.2.2`, `openpyxl>=3.1.5` |
| Import surface | `universal_utils` public names are unchanged |
| CLI | `qa-utils` and `universal-qa-utils` keep the same flags, JSON stdout, and exit codes 0, 2, and 1 |
| Robot keywords | Compare Excel Files, Compare CSV Files, Get Reconciliation Summary, Verify Reconciliation Passed |
| Result schema | `SCHEMA_VERSION` remains `1` |

`LIBRARY_VERSION` changes from `0.1.0` to `0.1.1` because it reports the package version. Callers that require the string `0.1.0` in `metadata.library_version` need to expect `0.1.1`. Comparison results do not otherwise change.

## Regression scope

Run from `universal-qa-utils` with the development extra installed:

```bash
python -P -m pytest tests integration_lab -q
```

The suite covers the comparison engine, reports, CLI exit codes, Robot Framework, the Playwright client, and the PowerShell process wrapper. The PowerShell tests require `pwsh`. They do not execute Tosca Commander.

Playwright tests call the Python engine. They do not install Tosca and they do not require a browser when the Playwright runner is present.

## Production deployment

1. Merge the approved branch to `master`.
2. Build the sdist and wheel from that commit.
3. Compare the tree with `v0.1.0` and confirm the behavior diff is limited to the maintenance items in `CHANGELOG.md`.
4. Upload only after a separate approval. Use a production token in the hidden Twine prompt. Do not reuse a TestPyPI token.
5. Download the published wheel with `--no-deps`, confirm its SHA-256, then install that local file.
6. Run `qa-utils --help`, one strict passing comparison, one strict business failure, and the Robot example from the installed wheel.

PyPI will keep serving 0.1.0 until 0.1.1 is uploaded. An install without `==0.1.1` will move to 0.1.1 after publication because 0.1.1 is a higher version.

## Rollback

PyPI does not let a project delete the only remaining release in a way that restores the prior file as if the new upload never happened. The rollback for a bad 0.1.1 upload is:

1. Yank `universal-qa-utils` 0.1.1 on PyPI. Yanking hides it from new installs and leaves existing installs unchanged.
2. Keep using `python -m pip install "universal-qa-utils==0.1.0"`.
3. Leave tag `v0.1.0` in place. If a `v0.1.1` tag was pushed for the bad release, do not move it. Publish a later fix as 0.1.2.
4. Do not force-push `master` and do not rebuild the 0.1.0 artifacts.

## Known limitations

- Windows Tosca Commander execution is pending. The plan is [tosca-windows-validation.md](tosca-windows-validation.md).
- Playwright and the Tosca PowerShell script remain repository adapters. They are not installed by `pip install universal-qa-utils`.
- The sdist test directory is not a complete checkout.
- Formula cells, merged cells, leading zeros in numeric Excel cells, and in-memory comparison have the same limits as 0.1.0.
- The PyPI page for 0.1.0 has no project URLs. Those URLs are added in the 0.1.1 metadata and appear on PyPI only after 0.1.1 is published.
